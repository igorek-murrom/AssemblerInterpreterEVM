# Практическая работа № 3. Вариант 15

## Этап 1. Перевод программы в промежуточное представление

Ассемблер читает программу для учебной виртуальной машины из CSV и
преобразует её в список команд. Каждая команда представлена парой целых чисел
`(A, B)`. Поле `A` содержит код операции, поле `B` содержит операнд.

## Этап 2. Формирование машинного кода

Каждая команда занимает 3 байта. Поле `A` занимает биты 0–3, поле `B`
начинается с бита 4. Старшие биты за пределами поля `B` равны нулю.
Первым записывается младший байт (little-endian). Двоичный файл содержит
байты команд в порядке исходной программы, без заголовка и разделителей.

## Этап 3. Интерпретатор и операции с памятью

Программа загружается из двоичного файла в общую память команд и данных.
Ячейка хранит целое число. В каждую ячейку начиная с адреса 0 загружается
одно трёхбайтовое машинное слово. При чтении ячейки, в которую ещё ничего
не записали, возвращается 0.

Интерпретатор читает очередное слово из общей памяти, выделяет поля `A`
и `B` и выполняет команду. Команды обрабатываются по возрастанию адресов.
Выполнение заканчивается после последней команды загруженной программы.
На этапе 3 реализованы `LOAD_CONST`, `READ_MEM` и `WRITE_MEM`.

## Этап 4. Арифметико-логическое устройство

Команда `NEG` снимает верхний элемент стека, меняет его знак и записывает
целое число в память по адресу из поля `B`. Ноль при этом остаётся нулём.

## Язык ассемблера

В каждой строке CSV указываются мнемоника и операнд через запятую.
Файл сохраняется в UTF-8, заголовок отсутствует. Мнемоники пишутся
прописными буквами, операнд задаётся десятичным числом без знака.
Пустые строки и пробелы вокруг значений игнорируются.

| Мнемоника | Поле A | Поле B | Диапазон B | Действие УВМ |
| --- | ---: | --- | ---: | --- |
| `LOAD_CONST` | 5 | Константа | 0–131071 | Помещает константу на стек. |
| `READ_MEM` | 9 | Смещение | 0–8191 | Читает память со смещением и помещает значение на стек. |
| `WRITE_MEM` | 1 | Смещение | 0–8191 | Записывает значение со стека в память со смещением. |
| `NEG` | 7 | Адрес | 0–262143 | Меняет знак значения со стека и пишет результат в память. |

`READ_MEM` снимает адрес со стека и прибавляет к нему смещение.
`WRITE_MEM` сначала снимает значение, затем адрес и прибавляет к адресу
смещение.

## Запуск

Требуется Python 3.10 или новее. Сборка и установка зависимостей не требуются.

### Ассемблер

```sh
./run.sh ИСХОДНИК.csv РЕЗУЛЬТАТ.bin [--test]
```

- Первый аргумент задаёт путь к исходному CSV-файлу.
- Второй аргумент задаёт путь к двоичному выходному файлу. При успешном
  ассемблировании файл по этому пути заменяется. Исходный и выходной
  файлы должны иметь разные пути.
- После записи программа выводит число ассемблированных команд.
- Флаг `--test` дополнительно печатает три байта каждой команды
  в шестнадцатеричном виде, по одной команде на строку.
- Флаг `--help` выводит справку по аргументам.

При ошибке чтения, разбора или записи ассемблер выводит причину в stderr
и завершается с кодом 1. При ошибке в CSV сообщение содержит номер строки.

### Интерпретатор

```sh
./run.sh --interpret ПРОГРАММА.bin ДАМП.json НАЧАЛО КОНЕЦ
```

- `ПРОГРАММА.bin` задаёт путь к машинному коду.
- `ДАМП.json` задаёт путь к файлу, который записывается после выполнения.
  Путь к дампу должен отличаться от пути к программе.
- `НАЧАЛО` и `КОНЕЦ` задают включительные границы адресов. Оба адреса
  должны быть неотрицательными, а `НАЧАЛО` не должно превышать `КОНЕЦ`.
- `./run.sh --interpret --help` выводит справку по интерпретатору.

Дамп — JSON-объект с адресами в виде строковых ключей и целочисленными
значениями. При ошибке интерпретации программа сообщает причину в stderr
и завершается с кодом 1. Ошибка выполнения содержит адрес команды.

## Пример ассемблирования

Файл `tests/specification.csv` содержит четыре команды из спецификации.

```csv
LOAD_CONST,338
READ_MEM,722
WRITE_MEM,123
NEG,577
```

```sh
./run.sh tests/specification.csv program.bin --test
```

Ожидаемый вывод

```text
Ассемблировано команд: 4
0x25, 0x15, 0x00
0x29, 0x2D, 0x00
0xB1, 0x07, 0x00
0x17, 0x24, 0x00
```

Проверка содержимого двоичного файла

```sh
od -An -tx1 program.bin
```

```text
 25 15 00 29 2d 00 b1 07 00 17 24 00
```

## Пример копирования массива

Программа `tests/copy_array.csv` записывает массив `[37, 0, 338, 131071]`
по адресам 100–103, затем копирует его в ячейки 104–107. Смещения 0–3
задают позиции элементов относительно начала каждого массива.

```sh
./run.sh tests/copy_array.csv copy_array.bin
./run.sh --interpret copy_array.bin memory.json 100 107
cat memory.json
```

Содержимое дампа

```json
{
  "100": 37,
  "101": 0,
  "102": 338,
  "103": 131071,
  "104": 37,
  "105": 0,
  "106": 338,
  "107": 131071
}
```

## Пример вычисления унарного минуса

Программа `tests/negation.csv` вычисляет унарный минус для чисел
`37`, `0`, `-37` и `131071`. Отрицательный операнд программа читает
из ячейки 200, куда записала первый результат. Перед вычислением для
нуля программа записывает в ячейку 201 число 99, чтобы проверить замену
существующего значения.

```sh
./run.sh tests/negation.csv negation.bin
./run.sh --interpret negation.bin memory.json 200 203
cat memory.json
```

Содержимое дампа

```json
{
  "200": -37,
  "201": 0,
  "202": 37,
  "203": -131071
}
```
